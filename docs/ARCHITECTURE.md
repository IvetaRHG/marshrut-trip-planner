# Архитектура

Документ описывает, из чего состоит приложение, как устроен рендер и почему
приняты те или иные решения.

## Компоненты

| Файл | Ответственность |
|---|---|
| `app/index.html` | Разметка всех секций, каркасы состояний (`loading`/`error`/`empty`), плавающая демо-панель. |
| `app/styles.css` | Дизайн-система на CSS-переменных, раскладка, адаптивность, анимации. |
| `app/app.js` | Данные поездки, состояние, рендер всех секций, работа с `localStorage`. |

Сборки нет: файлы подключаются напрямую, порядок важен — `styles.css` в
`<head>`, `app.js` в конце `<body>`.

## Данные

Все демонстрационные данные — константы в начале `app.js`:

- `TRIP` — название, даты, маршрут текстом, общий бюджет;
- `DAYS` — 7 дней, для каждого город, дата и два набора событий
  (`calm` / `intense`) с временем, категорией и стоимостью;
- `PACE_CONFIG` — подписи и подсказки для переключателя темпа;
- `BOOKINGS_INITIAL` — перелёт, отель, поезд, экскурсия и их статусы;
- `CHECKLIST_INITIAL` — 10 пунктов в 4 категориях;
- `BUDGET_CATEGORIES` — транспорт, отель, питание, экскурсии, прочее.

Данные отделены от рендера: чтобы изменить поездку, не нужно трогать
логику — достаточно отредактировать константы.

Даты поездки вычисляются при загрузке (`buildTripDates`): берётся
12–18 сентября **текущего** года, а если даты уже прошли — следующего.
Поэтому блок «Обратный отсчёт» всегда показывает осмысленное значение,
и демо не «протухает» со временем.

## Состояние и рендер

Единый объект `state` хранит выбранный день, темп, статусы бронирований и
отметки чек-листа. Каждая секция имеет свою точечную функцию:

```
state (день, темп, бронирования, чек-лист)
   │
   ├── renderCover()          обложка: даты, обратный отсчёт, маршрут
   ├── renderPaceToggle()     темп «Спокойно» / «Насыщенно»
   ├── renderRouteDays()      чипсы дней
   ├── renderRouteSchedule()  события выбранного дня
   ├── renderBudget()         прогресс, остаток, категории
   ├── renderBookings()       карточки бронирований
   ├── renderChecklist()      пункты и прогресс подготовки
   ├── renderTodayMobile()    блок «Сегодня» для узких экранов
   │
   └── renderAll()            вызывает все перечисленные
```

Клик пользователя меняет `state` и вызывает только нужный рендер
(переключение дня — `renderRouteSchedule` + `renderBudget`; подтверждение
бронирования — `renderBookings`). `renderAll()` используется при старте и
сбросе.

## Состояния интерфейса

Каждая секция проходит через машину состояний `showSectionState()`:

| Состояние | Что показывает |
|---|---|
| `loading` | карточки-скелетоны с анимацией пульсации |
| `error` | сообщение и кнопка «Повторить» |
| `empty` | заглушку «в этот день событий нет» |
| `success` | обычное содержимое |

Секция маршрута, бронирования, чек-лист и бюджет имеют собственные контейнеры
`*_stateContainer`, поэтому секции могут находиться в разных состояниях
одновременно. Плавающая панель «Демо состояний» (правый нижний угол) переводит
секции в любое состояние вручную — это сделано для проверки интерфейса
и записи демо.

## Хранение

`localStorage` с префиксом `routePlanner.*`:

- `routePlanner.bookings` — статусы бронирований;
- `routePlanner.checklist` — отметки чек-листа.

Чтение выполняется один раз при старте (`loadFromStorage`), запись — в момент
изменения. Кнопка «Сбросить учебные данные» удаляет ключи и возвращает
состояние к исходному. Ошибка доступа к `localStorage` (приватный режим)
обрабатывается и не ломает приложение.

## Безопасность

- Всё динамическое содержимое вставляется через `textContent` либо
  `escapeHtml()` — данные пользователя (отметки чек-листа, статусы) не могут
  попасть в разметку как HTML.
- Внешних запросов нет: ни CDN, ни шрифтов, ни картинок. Приложение работает
  офлайн и не отправляет данные куда-либо.
- Единственное хранилище — `localStorage` браузера пользователя.

## Адаптивность

Три контрольные точки из задания:

| Ширина | Компоновка |
|---|---|
| ≥ 1100 px | двухколоночная: слева маршрут/бронирования/чек-лист, справа бюджет |
| 768–1100 px | одноколоночная, секции друг под другом |
| ≤ 640 px | режим «Сегодня»: обложка, ближайшее событие, нижняя навигация |

Раскладка построена на Grid/Flexbox без media query-дублирования стилей:
базовые стили мобильные, всё более крупное — через `@media (min-width: ...)`.
Горизонтальная прокрутка исключена (`overflow-x: clip` на корне,
`min-width: 0` в grid-ячейках).

## Доступность

- семантические теги: `header`, `main`, `section`, `nav`, `complementary`;
- 26 ARIA-атрибутов: `aria-label`, `aria-pressed` на переключателях,
  `aria-live` для уведомлений (toast);
- полный доступ с клавиатуры: все интерактивные элементы — `<button>`,
  фокус видим;
- `prefers-reduced-motion: reduce` отключает плавную прокрутку и анимации.

## Точки расширения

- **Реальные данные** — заменить константы на `fetch()` JSON-файла; рендер
  и состояния уже готовы к асинхронной загрузке.
- **Несколько поездок** — добавить идентификатор поездки в ключи `localStorage`.
- **Тёмная тема** — дизайн-система на CSS-переменных, меняется один блок
  `:root`.
- **PWA** — манифест и service worker: приложение уже полностью офлайн.
